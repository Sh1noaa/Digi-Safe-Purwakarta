3.3 Bagaimana Cara Kerja "Masuk dengan Google" (OAuth 2.0)?

Kredensial aplikasi disimpan aman di file .env (GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, GOOGLE_REDIRECT_URI) dan dibaca melalui config/services.php baris 38–42. Alurnya ditangani oleh 2 rute di routes/web.php baris 86–87:

Gambar 3.1 — Alur Google OAuth 2.0 di AuthController.php (Baris 107–284)
  • Kenapa tidak pakai package tambahan? Di AuthController.php baris 176–205, kita memakai HTTP client bawaan Laravel (Http::asForm()->post(...)) langsung ke endpoint resmi Google sehingga ringan dan mudah dikontrol untuk Web maupun mode APK (?mode=mobile yang mengembalikan token ke deep-link digisafe://auth/callback).
  • Kenapa ada fallback Cache pada state? (baris 127 & 166–170): Di localhost terkadang pengguna membuka localhost:8000 tetapi redirect URI mengarah ke 127.0.0.1:8000 (cookie session tidak lintas host). Menyimpan state di Cache selain Session membuat login Google tetap lancar tanpa error kedaluwarsa.
  • Bagaimana jika email Google sudah pernah daftar manual? Di findOrCreateGoogleUser() (baris 239–279): sistem mencari dulu berdasarkan oauth_uid. Jika belum ada, sistem mencari berdasarkan email. Jika email ketemu, akun lama otomatis ditautkan (oauth_provider = 'google'). Jika belum pernah daftar sama sekali, sistem membuatkan akun baru beserta username unik via generateUniqueUsername() (baris 281–301).

Profil, Cropper Foto & GIF Animasi, Select Your Role, & Privasi

4.1 Cropper Interaktif Foto Profil (1:1) & Banner (16:5) — Mendukung GIF Animasi!

Penguji mungkin bertanya: "Bagaimana cara user memotong foto profil dan banner GIF tanpa membuat animasinya mati, padahal di PHP lokal ekstensi GD tidak aktif?"

Penjelasan Teknis Sederhana: Pemotongan gambar dikerjakan 100% di sisi browser (Client-Side) lewat resources/js/image-cropper.js dan komponen Alpine profileImageCropper() di resources/js/app.js (baris 155–382):
  • Untuk JPG / PNG / WebP: Menggunakan HTML5 <canvas> (cropStaticImage) untuk menggambar ulang area yang dipilih user ke resolusi 512x512 (avatar) atau 1280x400 (banner).
  • Untuk GIF Animasi: Library gifuct-js membongkar setiap frame GIF beserta delay dan disposal method-nya, memotong masing-masing frame sesuai koordinat zoom/geser user, lalu library gifenc menyusunnya kembali menjadi file .gif animasi baru!
  • Cara Masuk ke Form HTML: File hasil crop dimasukkan ke dalam <input type="file"> memakai API browser new DataTransfer() (baris 347–351 di app.js), sehingga ketika tombol Simpan Perubahan diklik, form mengirim file yang sudah terpotong ke ProfileController@update (baris 38–111), yang menyimpannya ke public/images/avatars/ & public/images/banners/ (sekaligus salinan di storage/app/public/ agar aman di hosting tanpa storage:link).

BAB 8

Arsitektur Ganda: Localhost (Demo UKK) vs Hosting (RumahWeb)

Mode Localhost (Demo UKK)

Memakai .env.local → disalin otomatis ke .env oleh skrip JALANKAN-LOCALHOST-UKK.bat. Terhubung ke MySQL XAMPP (digi_safe_db), APP_URL=http://127.0.0.1:8000, dan GOOGLE_REDIRECT_URI=http://127.0.0.1:8000/auth/google/callback. Di AppServiceProvider::register() (baris 19–37), PHP Windows otomatis mengecek & menyalakan MySQL jika belum aktif.

Mode Production (Hosting RumahWeb)

Memakai .env.hosting (APP_ENV=production, APP_DEBUG=false, APP_URL=https://digisafepurwakarta.web.id). File .htaccess di root mengarahkan request public_html ke folder public/ sambil memblokir akses langsung ke .env dan folder sensitif. AppServiceProvider otomatis memaksa HTTPS di production agar aset CSS/JS tidak terblokir Mixed Content.

Kenapa Shared Hosting Tanpa SSH (Tidak Bisa php artisan migrate) Tetap Aman? Karena di AppServiceProvider::boot() (baris 46–48) selalu dijalankan 3 auto-initializer: User::ensurePreferenceColumns(), MinigameLevel::ensureInitialized(), dan SocialSchemaHelper::ensureReady(). Jika ada tabel atau kolom baru (seperti edukasi_requests, friendships, chat_messages, specialty_role) yang belum ada di database hosting, sistem akan membuatnya otomatis saat pertama kali dibuka!
BAB 9

Bank 20 Pertanyaan Penguji UKK & Jawaban Siap Pakai

1. "Itu navbar Beranda kok awalnya transparan putih, pas di-scroll ke bawah berubah jadi solid putih? Kodingannya di mana?"
Ada di resources/views/layouts/app.blade.php baris 19–39. Kita pakai Alpine.js x-data="{ scrolled: false }" dan listener @scroll.window="scrolled = window.scrollY > 50". Saat scroll melewati 50px, class-nya berubah dinamis memakai :class menjadi bg-white/95 text-ink backdrop-blur-md (atau biru gelap di Dark Mode).
2. "Bagaimana cara mengamankan form Login dan Register dari serangan CSRF atau pembajakan session?"
Setiap form POST menyertakan token @csrf yang diverifikasi otomatis oleh Laravel. Password di-hash menggunakan Bcrypt (Hash::make()), bukan MD5 atau teks biasa. Saat login berhasil, kita memanggil $request->session()->regenerate() untuk mengganti ID session (mencegah Session Fixation), dan saat logout kita memanggil invalidate() + regenerateToken().
3. "Bagaimana alur teknis Login dengan Google bisa langsung masuk tanpa isi form register?"
Di AuthController.php (baris 107–284), method redirectToGoogle() mengarahkan user ke OAuth Google sambil membawa state acak anti-CSRF. Setelah user memilih akun Gmail, Google mengirim parameter code ke handleGoogleCallback(). Server menukar code tersebut menjadi access_token, mengambil data email & nama dari Google UserInfo API, lalu findOrCreateGoogleUser() menautkan akun yang sudah ada atau otomatis membuat akun baru dengan username unik.
4. "Kalau ada user biasa yang iseng ngetik URL /admin di address bar, apakah bisa masuk?"
Tidak bisa. Seluruh rute prefix /admin di routes/web.php baris 95 dilindungi oleh middleware ['auth', 'admin']. Class AdminMiddleware.php (baris 15–17) mengecek apakah role user adalah admin atau owner; jika bukan, sistem langsung menolak dengan abort(403).
5. "Kenapa akun Owner di Panel Admin tidak ada tombol Edit atau Hapusnya?"
Karena kita menerapkan proteksi mutlak baik di tampilan (admin/user/index.blade.php baris 89–96) maupun di backend (Admin/UserController.php baris 27–31) menggunakan pengecekan $user->isOwner(). Siapa pun—termasuk admin lain—tidak dapat mengubah atau menurunkan role Owner.
6. "Bagaimana cara kerja Request Edukasi & Bot Digika yang mengirim pesan otomatis?"
User mengirim request di halaman /edukasi (tersimpan ke tabel edukasi_requests). Saat Admin mengklik Setujui atau Tolak di Admin\EdukasiController@evaluateRequest() (baris 116–182), backend otomatis memanggil User::ensureBotDigika() lalu menyimpan pesan hasil evaluasi ke tabel chat_messages. Widget chat di browser user melakukan polling ke /chat/unread-count setiap 5 detik sehingga notifikasi & pesan Bot Digika muncul otomatis.
7. "Kenapa Bot Digika tidak muncul di daftar user Beranda atau Leaderboard?"
Karena pada model User.php (baris 136–140) dibuat query scope scopeHumans() yang menyaring akun sistem bot.digika@digisafe.id. Scope ini dipakai di BerandaController, LeaderboardService, Admin\UserController, Admin\ReportController, dan SocialChatController::searchUsers().
8. "Bagaimana cara crop gambar/GIF di Edit Profil tanpa mematikan animasi GIF-nya?"
Di resources/js/image-cropper.js, gambar JPG/PNG dipotong memakai HTML5 Canvas, sedangkan file .gif didekode frame per frame oleh gifuct-js, dipotong setiap framenya sesuai koordinat viewport, lalu disatukan kembali menjadi animasi GIF baru oleh gifenc dan dimasukkan ke input file lewat DataTransfer.
9. "Pada daftar member Beranda yang berjalan terus, bagaimana bisa di-drag kanan kiri tanpa bentrok sama klik kartu?"
Di resources/js/app.js (memberMarquee() baris 7–150), pergerakan dijalankan via requestAnimationFrame. Sistem mencatat jarak geser pointer (dxTotal). Jika geseran kurang dari 6px dianggap klik normal (langsung buka link), jika lebih dari 6px dianggap drag dan event klik sesaat diblokir di fase capture (handleClickCapture).
10. "Apa fungsi file SimpleXlsxExporter.php? Kenapa tidak pakai PhpSpreadsheet?"
SimpleXlsxExporter.php membuat file Excel .xlsx resmi (berbasis arsip ZIP XML OpenXML) secara mandiri memakai ekstensi PHP ZipArchive tanpa butuh library vendor raksasa atau memori besar, sehingga sangat cepat dan ringan saat dijalankan di shared hosting RumahWeb.
11. "Bagaimana cara kerja sistem voting Most Helpful di Forum agar satu orang tidak bisa spam like?"
Di ForumController@voteJawaban() (baris 117–160), setiap vote disimpan ke tabel jawaban_forum_votes dengan cek jawaban_id dan user_id. Jika user klik tombol yang sama, vote dihapus (toggle); jika klik berlawanan, tipe vote diganti. Jawaban dengan total 👍 terbanyak dan selisih positif otomatis diberi badge Most Helpful.
12. "Apakah website ini juga terhubung dengan aplikasi Android (APK)?"
Ya. Seluruh endpoint di routes/api.php (seperti /api/beranda, /api/edukasi, /api/minigame, /api/forum, /api/auth/google) menggunakan autentikasi Bearer Token (ApiTokenAuth) dan database MySQL yang sama. Jadi setiap kali Admin mengupload modul atau soal di website, aplikasi APK otomatis ikut terupdate.
13. "Bagaimana cara file .htaccess melindungi file sensitif seperti .env di hosting RumahWeb?"
Di file .htaccess root baris 16–21, aturan RewriteRule ^(\.env.*|\.git.*|...) - [F,L,NC] langsung mengembalikan status 403 Forbidden jika ada yang mencoba mengakses .env, .git, app/, atau database/ lewat browser, sementara request web normal diteruskan ke public/$1.
14. "Apa bedanya tailwind.config.js/Vite saat di localhost vs di hosting RumahWeb?"
Saat pengembangan di localhost kita menjalankan npm run build (Vite) yang mengompilasi app.css dan app.js menjadi file statis di folder public/build/. Di hosting RumahWeb, server tidak perlu menjalankan Node.js karena Laravel cukup membaca public/build/manifest.json lewat tag @vite(...).
15. "Bagaimana fitur Dark Mode dan Bahasa (ID/EN) bisa tersimpan permanen per akun?"
Saat user menyimpan pengaturan di settings-modal.blade.php (PUT /profile/settings), ProfileController@updateSettings() menyimpan kolom locale dan theme ke tabel users sekaligus ke session. Lalu middleware SetUserPreferences.php (baris 12–44) selalu membaca preferensi tersebut di setiap halaman dan menambahkan class dark ke tag <html>.
16. "Bagaimana cara kerja sistem Chat & Pertemanan agar orang asing tidak sembarangan spam?"
Di SocialChatController.php (baris 237–250), saat pengirim pertama kali chat user yang belum berteman, status relasi di tabel friendships menjadi pending (maksimal 3 pesan pembuka). Penerima harus klik Konfirmasi terlebih dahulu di widget chat (acceptFriendRequest) agar obrolan dua arah terbuka penuh, atau klik Tolak untuk memblokir.
17. "Bagaimana Admin menambah atau mengubah level kesulitan di Minigame?"
Di tab Soal Minigame Panel Admin (Admin\MinigameController.php baris 133–230), Admin bisa menambah/mengedit baris di tabel minigame_levels (mengatur nama level, durasi timer detik, poin benar, penalti salah, & HP awal). Saat user bermain di MinigameController@play(), seluruh level aktif otomatis dimuat dari database.
18. "Bagaimana sistem membedakan redirect setelah Login antara User biasa dan Admin?"
Di AuthController.php baris 42–46 (dan baris 228–232 untuk Google Login), sistem mengecek Auth::user()->hasAdminAccess() (true jika role admin atau owner). Jika true diarahkan ke route('admin.dashboard'), jika user biasa diarahkan ke route('beranda') (atau halaman intended yang sebelumnya ingin diakses).
19. "Bagaimana validasi upload gambar/GIF bekerja jika di PHP hosting ekstensi fileinfo belum aktif?"
Di app/Services/UploadValidationHelper.php baris 13–40, sistem mengecek extension_loaded('fileinfo'). Jika aktif, memakai validasi mimes:jpg,jpeg,png,webp,gif bawaan Laravel; jika tidak aktif, otomatis memakai fallback validasi ekstensi + fungsi PHP @getimagesize() untuk memastikan file benar-benar gambar/GIF asli, bukan file berbahaya yang diubah ekstensinya.
20. "Bagaimana proses upload avatar/banner tetap tampil di Shared Hosting RumahWeb padahal tidak ada akses SSH php artisan storage:link?"
Di ProfileController.php baris 65–104, file hasil upload disimpan langsung ke folder publik public/images/avatars/ dan public/images/banners/ (sekaligus disalin ke storage/app/public/), ditambah rute fallback /storage/{path} di routes/web.php baris 133–142 sehingga gambar selalu tampil 100% tanpa perlu symlink.
